# M0: native video player

> Historical M0 implementation/evidence. Current native MSDF text, analytic widget rendering and three-layout behavior are documented in [M2e](M2E.md).

Implemented and exercised on Windows x64 on 2026-11-14. The five Valencia projects are in `src/`; external project references are grouped under `Infrastructure` in the solution. No upstream source changes were required.

## Working path

`Valencia.App` creates a native window with Machina transport controls. InputMan maps keyboard transitions into semantic transport actions. Native file selection and an optional command-line path open local MP4/MKV files. Metadata, playback position and errors appear in the window.

`Valencia.Media` uses FFmpeg.AutoGen 7.1.1 with matching FFmpeg 7.1 shared libraries. Independent video and audio workers own separate decoder contexts; bounded queues prevent audio prebuffering from blocking behind video. Video is software-decoded, converted to SDR RGBA8 and uploaded into a persistent Aurelian texture. Audio is resampled/downmixed to stereo 48 kHz float PCM and streamed through NAudio.WinMM 3.3.0. The WaveOut device position drives video scheduling; queued underrun silence is excluded from media time. Video-only files use a monotonic clock.

Play/pause, five-second relative seeks, clicking the position bar, end-of-file and replay are implemented. Seeking opens a fresh decoder generation, seeks backward and decodes to the target presentation interval. Cancellation releases blocked channel writers; the audio callback stops before its provider is disposed. Native file probing/reads are synchronous inside workers: cancellation does not interrupt an FFmpeg call blocked on local storage.

`Valencia.Core` retains rational source timestamps and exposes checked conversions into a 254,016,000,000-tick sequence timebase. Conversion uses checked integer arithmetic, truncating toward zero for timestamps outside that timebase's exact grid. Playback scheduling uses seconds; future persisted edit boundaries must use the exact Core representation. Core has no codec, UI, rendering or storage dependencies.

Aurelian owns Vulkan rendering/presentation. The small rendering adapter supplies required extensions from the actual native window and source-links the existing Machina presentation translator. The linked Copeland shader has a checked-in compiled artifact, so normal startup does not require DXC. Machina's current bitmap UI raster is uploaded separately from video; there is no browser runtime. Deliverance is referenced for the M1 integration boundary; scripting contains only a reserved ABI identity.

## Executed validation

Commands:

```powershell
.\scripts\Build.ps1
.\scripts\Smoke.ps1 -AppPath artifacts/publish/win-x64/Valencia.App.exe
```

The Release build and framework-dependent `win-x64` publish succeeded. All **14 tests passed**, with zero failures or skips, against current compiled source. Tests generate encoded H.264/AAC fixtures and cover MP4/MKV decoding, B-frame draining/order, random seeks, independent audio resampling, cancellation under full queues, nonzero container timestamps, invalid input, exact time conversion/overflow, underrun clock accounting and keyboard event edges.

The published executable passed both real-device smoke runs:

| Fixture | GPU | Audio | Max sampled video/audio-clock difference | Presented / uploaded frames |
|---|---|---|---|---|
| Six-second MP4, H.264/AAC, 640×360/30 | NVIDIA GeForce RTX 3070 | NAudio 3 WaveOut | 32.3 ms | 472 / 93 |
| Same streams remuxed into MKV | NVIDIA GeForce RTX 3070 | NAudio 3 WaveOut | 33.0 ms | 473 / 92 |

Both runs exercised real decode, presentation, audio-device clock advancement, pause stability, seek to 3.2 seconds, window resize, end-of-file and GPU readback agreement with decoded pixels. Each sampled playback clock/frame differences more than 400 times. Acceptance is a maximum 150 ms difference, pause drift below 15 ms, seek-frame distance below 80 ms, and more than 30 uploads/presents. These are short fixture results, not perceptual lip-sync or long-recording qualification. The installed Vulkan validation layer was available; this smoke does not count validation callback errors.

Native UI automation separately opened the MKV through the file picker, observed changing video/transport after Space, sought with J and the pointer position bar, and exercised the Machina Play button. A rapid-key edge-loss issue found during this check was fixed by queuing native key transitions before InputMan evaluation; two regression tests cover this behavior. Final published smokes ran after the correction.

Full local outputs are under `artifacts/local/tests/m0.trx` and `artifacts/local/smoke-{mp4,mkv}/` (JSON plus seek/final PNGs). Compact results are retained in `docs/validation/`. Audio samples and real output-device progression were verified programmatically; audible quality still needs a listener.

## Delivery and limits

Run `artifacts/publish/win-x64/Valencia.App.exe`, optionally passing a local media path. Keep the published directory together. It requires the .NET 10 Desktop Runtime, a Vulkan driver and matching shared FFmpeg DLLs; FFmpeg is not bundled. See the root README for discovery paths and controls.

This is Windows-only M0, with software decode and synchronous CPU-to-GPU transfer. It plays a single video stream and selected audio stream, not a multi-track composition. HDR PQ/HLG is explicitly rejected. Rotation, non-square pixels, full color management, arbitrary timestamp discontinuities, device hot swapping, long OBS recordings and large/high-bitrate media remain unqualified. No timeline editing, save/reopen, export, scripts or agents are implemented. The next functional milestone is M1; these short playback results do not establish full NLE readiness.
